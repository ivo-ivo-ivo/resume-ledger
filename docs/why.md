# Why a ledger, not a generator

Most AI resume tools read the job description and write toward it. The output is fluent and the numbers are whatever makes the paragraph work. Candidates then carry those numbers into interviews they cannot survive.

resume-ledger reverses the order. First, what happened is recorded as rows: the fact, the number, its definition, the source, who did what, whether it is live or planned. The user confirms every row. Only then is anything written, and a script refuses a draft that contains a number the ledger does not.

Three things follow. Conflicts surface early, because the second time a candidate describes the same project differently, the check asks which version stands. Tailoring becomes a mapping exercise, requirement to rows, with gaps left visible instead of papered over. And a portfolio can be written in its own words without drifting from the resume, because both draw from the same ledger.

It costs more up front than pasting a JD. It pays back the first time an interviewer asks "how exactly was that 30% measured".

# 为什么是账本，不是生成器

市面上的 AI 简历工具大多读 JD 往上写，文字通顺，数字则是"让这段话成立"的那个数。候选人带着这些数字进面试，一问就穿。

resume-ledger 把顺序倒过来。先把发生过的事记成账本行：事实、数字、口径、来源、谁做了什么、是上线还是规划。每一行都由本人确认。然后才写，而且脚本会拒绝任何含有账本之外数字的草稿。

由此带来三件事。冲突会早暴露：同一个项目第二次说法不一样时，检查会问哪一版算数。定向变成映射：JD 要求对账本行，缺口留在明面上而不是用文案糊上。作品集可以用自己的话写而不与简历漂移，因为两者取自同一本账。

它比贴 JD 多花前期功夫。回本的时刻是面试官问出"那个 30% 具体怎么算的"那一刻。
