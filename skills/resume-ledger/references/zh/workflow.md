# 工作流与口述问答协议（zh）

## 总顺序

1. 初始化项目（`init.py`）。
2. 采集事实：按下面的问答协议问，每条确认后的事实用 `fact_add.py` 写入账本。
3. 用户填 `rules.md`：红线词、禁用写法、允许写法。
4. 写内容：`content/<版本>.md`，一个版本一个文件。
5. 构建与校验：`build.py`、`check_numbers.py`、`scan.py` 三项全过，并把 PDF 页数读给用户。
6. 登记：`registry_add.py`，投递结果与反馈回填到登记表。

## 口述问答协议

目的：把用户脑子里的经历变成账本行，每一行都有口径、来源、角色边界、状态。模型负责问和整理，不替用户下结论。

**分轮**
- 每轮最多 10 题，必须级在前，有则更好在后。能给选项勾选的就给选项，不连环追问。
- 第一轮问"定文档骨架"的问题：时间线、范围边界、机制、评测方式、效果口径、合规与人在回路、分工。
- 用户已经登记过的事实不重问；问之前先读账本。

**每条新事实四件套**（缺一不入账）
1. 口径：分子分母、周期、相对还是绝对、范围。
2. 来源：口述日期、文档、系统导出。
3. 角色边界：本人做了什么，谁做了其余的。
4. 状态：live / pilot / planned。

**冲突检查先于下一轮**
- 新陈述与账本已有行、与本会话早先的陈述逐条对照；每处冲突列出两个版本，问用户哪个成立。
- 不替用户选，不静默取其一。
- 同一分歧问两轮仍不消，停下，请用户提供材料，不再问第三轮。

**常规做法可以当选项，不能当事实**
- 用户问"市面上一般怎么做"时，可以列出常见做法让他对照勾选。
- 勾选结果入账，列出的选项本身不入账。用户没做的就是没做，写成"第一版未做、列入下一步"比写上更可信。

**退出条件**
- 骨架问题答完、冲突清零，先给叙事方案（章节与每节材料来源），用户点头再写正文。

## 数字规则

- 一个数字在同一份简历里最多出现两处：核心优势一处、正文一处。
- 相对值与绝对值必须标明；"提升 20%"不合格，"相对提升 20%"或"+20 个百分点"合格。
- planned 状态的事实只能进"下一步"，`check_numbers.py` 会标出只被 planned 行支撑的数字。
- 12 以下的裸整数脚本不对账，模型仍须保证它在账本里。

## 作品集与简历的关系

- 作品集去识别化，口径可以与简历不同，但每个数字仍要有 scope=portfolio 或 both 的账本行。
- 旗舰册 8 页封顶，短篇 3 页；规划项一律写在"下一步"，不计入成果。
- 两份文档之间的叙事要能互相解释：简历写"直接负责 4 人小组"而作品集写"核心团队"，面试要能接上。
